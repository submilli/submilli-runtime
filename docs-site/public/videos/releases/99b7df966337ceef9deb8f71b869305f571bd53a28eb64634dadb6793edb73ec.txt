We want the agent to total Northwind’s charges. A human defines this blueprint: make the billing package available, deny by default, and allow a charge lookup only for the customer supplied by the application. Here, that is Northwind.

The agent writes this program in Submilli’s curated subset of TypeScript. It imports the billing package, reads Northwind’s charges, and totals the amounts. The runtime runs the code; the package exposes the lookup.

Submilli first checks the code against its supported language, standard APIs, and the packages selected by the blueprint. Unknown APIs and unavailable imports fail here, before execution. Valid code still needs permission for protected operations.

Before reading charges, the package explicitly asks Submilli to check the operation and customer ID. The runtime applies the blueprint. Northwind matches, so the lookup proceeds. This example uses a local billing ledger.

Change only the customer to Initech. The code still passes language checking. The permission check now denies the lookup: Initech does not match the application’s Northwind context.

Northwind’s program returns two charges, totaling six thousand one hundred and fifty cents. The language limits the code. The blueprint limits permitted operations and arguments. People define the rules; Submilli enforces the checks.
