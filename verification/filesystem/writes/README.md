# Byte writes without a filesystem journal

`write_bytes` repeats a straight-line atomic replacement using replay-supplied
bytes. There is no SQL request, fingerprint, prepared checkpoint or filesystem
receipt for this call. Its private path is deterministic from the run and effect.
The name is `<effect-id>.replacement` directly in the run's private directory,
so writes leave no empty per-effect directories. Every attempt unlinks a stale
temporary name before validating public hard links, creates a fresh inode, writes
and syncs it, renames it over the target and syncs the target and private directories.

`WriteRecovery.tla` separates the native steps from the framework's completion
record. `phase` is volatile execution position, not a saved state machine.
`history` belongs to the execution framework. The modeled framework supplies
identical input, records completion after the call returns, skips completed
writes on restart and admits later effects only after durable completion.
Production integration of that framework is future work. A direct call with an
old effect ID still writes: the filesystem does not suppress completed calls.

The roots and mount configuration stay fixed and exclusively owned; cancelled
workers drain before retry. Input is regenerated by replay, never stored by the
filesystem. A successful file/directory sync survives the modeled power crash;
unsynchronized directory entries can persist independently. A crash during rename
may retain both the temporary and public names for the same inode. Unlinking the
temporary name and creating a fresh inode prevents retry from truncating the
published file. Neither a hard link nor a content hash is required by the algorithm.

The bounded checks cover existing and absent targets, up to two crashes, atomic
visible replacement, durable completion, preservation of later effects and
completion after finite failures under fair retries. Negative variants must
produce named counterexamples when they reuse the temporary inode, skip file or
destination-directory synchronization, replay completed writes, or admit a later
effect while the write remains pending. Witnesses require both an outer
completion gap followed by a successful retry and the stale-private-alias case.

The [quota model](../quotas/README.md) separately checks current-size deltas on
repeated publication. Rust tests inject failures, simulate a stale private alias,
cover empty writes, full quota and stale-alias retries with more than 10,000
unrelated recovery entries, verify no filesystem SQL row is created, and
kill a process at six write boundaries before explicitly retrying the same input.
Those process tests establish process-crash behavior; the TLA+ storage abstraction
covers power-crash ordering. These are bounded protocol checks, not proofs of Rust,
hardware, arbitrary filesystems or the future framework implementation.

Writer close still uses its journal and retained replacement file, covered by
[writer](../writers/README.md) and [namespace](../namespace/README.md) models.
Append still needs its saved starting offset so retry cannot duplicate bytes.

```sh
python3 verification/check.py --model filesystem/writes
```
