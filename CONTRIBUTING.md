# Contributing to Submilli

Contributions are welcome: bug reports, feature ideas, documentation improvements,
and pull requests all help us build a better runtime.

## Start with the problem

For new features or larger changes, we encourage you to open an
[issue](https://github.com/submilli/submilli-runtime/issues) or start a GitHub
Discussion before writing code. This is a suggestion, not a requirement. It gives
us a chance to understand your use case and discuss the approach before you spend
time on an implementation.

We especially value hearing what you need Submilli to do. Tell us:

- What are you trying to build or accomplish?
- What is missing, difficult, or getting in your way?
- What would a useful outcome look like? A small example helps.

A short, informal description is enough. You don't need a formal proposal or a
solution worked out in advance.

We use coding agents extensively and prefer to work through feature design and
implementation with them. For feature requests, a clear explanation of the need
is often the most helpful contribution you can make. Opening an issue is a
complete contribution in its own right; there's no expectation that you'll
implement it yourself.

## Report a bug

Open an issue with a small reproduction, what you expected, and what happened
instead. Include your Submilli version, operating system, and any relevant error
output. Remove credentials and other private information from examples and logs.

## Submit a pull request

PRs are welcome too. Small fixes and documentation improvements can go straight
to a PR; you're also welcome to propose an implementation for a larger change.
Starting a conversation first simply helps us agree on scope and direction.

Keep the change focused, explain the problem it solves, and link any related
issue or discussion. For behavior changes, include a test that demonstrates the
fix or feature and describe how you verified it.

See [CLAUDE.md](CLAUDE.md) for the repository's development conventions and
verification commands, and [docs-site/README.md](docs-site/README.md) for working
on the documentation website.

Whether you write the code yourself or use an agent, please review the changes
and be prepared to explain how they work.

## Contributor License Agreement

You have to sign our [CLA](CLA.md) during your first pull request, otherwise
we're not able to accept your contributions.

Signing uses [CLA assistant](https://cla-assistant.io). When you open your
first pull request, it posts a comment with a link: follow it, sign in with
GitHub, and click "I agree". The pull request's CLA check then turns green, and
you won't be asked again.

Thank you for helping improve Submilli.
