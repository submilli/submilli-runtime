{{- else if eq .Values.service.type "ClusterIP" }}

AUTHENTICATION
--------------
{{- if not .Values.auth.enabled }}
  auth.enabled is FALSE. THE API IS COMPLETELY UNAUTHENTICATED.

  There is no token and no per-request identity. Anything that can reach port
  {{ .Values.server.port }} can execute arbitrary code in the sandbox, register and rewrite
  blueprints, read back results, and stop the process via POST /v1/shutdown.
  Network reachability is the only access control. Do not run this way outside
  a throwaway cluster.
{{- else }}
  Every route except /healthz needs `Authorization: Bearer <token>`. There
  are two tokens:

    admin   every route
    user    run code, sessions, MCP, and the read-only blueprint prompt and
            package documentation routes; 403 on everything else

  Give agents the user token. No token, or an unknown one, is a 401.
{{- if .Values.auth.existingSecret }}

  They are read from your Secret {{ $secret }} (auth.existingSecret).
{{- else }}

  They were generated into the Secret {{ $secret }} and are kept across
  upgrades, and across `helm uninstall`.

  If this release is rendered without cluster access (Argo CD, or
  `helm template | kubectl apply`), the chart cannot read that Secret back and
  the tokens change on every render. Set auth.existingSecret there.
{{- end }}

  Read them:
    kubectl get secret {{ $secret }} -n {{ .Release.Namespace }} -o jsonpath='{.data.{{ .Values.auth.adminTokenKey | replace "." "\\." }}}' | base64 -d
    kubectl get secret {{ $secret }} -n {{ .Release.Namespace }} -o jsonpath='{.data.{{ .Values.auth.userTokenKey | replace "." "\\." }}}' | base64 -d

  {{- if not .Values.tls.enabled }}
  Use one:
    TOKEN=$(kubectl get secret {{ $secret }} -n {{ .Release.Namespace }} -o jsonpath='{.data.{{ .Values.auth.adminTokenKey | replace "." "\\." }}}' | base64 -d)
    curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:{{ .Values.service.port }}/v1/status

  {{- else }}
  Use `submilli server status --server https://<certificate-hostname>:{{ .Values.service.port }}`
  with SUBMILLI_SERVER_TOKEN_FILE pointing at a file holding the admin token.
  {{- end }}

  Tokens are read at boot. After changing the Secret:
    kubectl --namespace {{ .Release.Namespace }} rollout restart statefulset/{{ $fullname }}
{{- end }}

NETWORK
-------
{{- if not .Values.networkPolicy.enabled }}
  networkPolicy.enabled is FALSE. Nothing restricts which pods can reach this
  server. In a shared cluster that means every pod in every namespace
{{- if .Values.auth.enabled }}, and a
  token is all that stands between each of them and code execution.
{{- else }}, and with
  auth.enabled also false every one of them can execute code on it.
{{- end }}
{{- else if not .Values.networkPolicy.allowFrom }}
  A default-deny NetworkPolicy is installed and networkPolicy.allowFrom is
  empty, so nothing but the chart's own tests can reach the server yet. Add the
  workloads that should talk to it.
{{- else }}
  A default-deny NetworkPolicy admits only the peers in networkPolicy.allowFrom.
{{- if .Values.auth.enabled }}
  It is the second layer behind the tokens, not a replacement for them.
{{- end }}
{{- end }}
{{- if .Values.ingress.enabled }}

  ingress.enabled is TRUE. A code-execution API is now published outside the
  cluster
{{- if not .Values.auth.enabled }} WITH NO AUTHENTICATION. Put an authenticating proxy in front of
  it, or turn auth.enabled back on.
{{- else if not .Values.ingress.tls }}, and ingress.tls is empty: the bearer token crosses the
  network in the clear unless something in front terminates TLS.
{{- else }}, protected only by its bearer tokens. Treat the admin token
  accordingly.
{{- end }}
{{- end }}

{{- if .Values.networkPolicy.enabled }}

  A NetworkPolicy is enforced only if your CNI implements one. Where it does
  not, the object is accepted and silently does nothing. Verify rather than
  assume:
    helm --namespace {{ .Release.Namespace }} test {{ .Release.Name }}

  kubectl port-forward tunnels through the API server and bypasses
  NetworkPolicy entirely. Anyone with pods/portforward permission reaches this
  server regardless of the policy
{{- if .Values.auth.enabled }}, though still not past the tokens.
{{- else }}.
{{- end }}
{{- end }}

BLUEPRINTS AND SECRETS
----------------------
  Apply blueprints using `submilli server blueprint apply` with an admin token.
  Populate their store secrets first using `submilli server secret put`.
{{- if .Values.secretStore.enabled }}
  The encryption key is in Secret {{ include "submilli.secretStoreSecretName" . }}.
  Back up this Secret along with the persistent volume.
{{- end }}
{{- if not .Values.persistence.enabled }}

STORAGE
-------
  persistence.enabled is FALSE. Sessions, installed packages, secrets, and any
  blueprint registered through the API are lost when the pod restarts.
{{- else }}

STORAGE
-------
  The PersistentVolumeClaim survives `helm uninstall` by design; delete it by
  hand when you want the data gone:
    kubectl --namespace {{ .Release.Namespace }} delete pvc -l app.kubernetes.io/instance={{ .Release.Name }}

  Node-local volumes cannot follow a pod to another node. Surviving a node drain
  needs a StorageClass whose volumes are not node-local.
{{- end }}

{{- if .Values.tls.enabled }}
Native HTTPS is enabled on port {{ .Values.server.port }}.
Clients must trust the certificate and use a hostname in its subject alternative names.
The CLI offers an interactive trust prompt for a self-signed certificate.
After rotating Secret {{ .Values.tls.existingSecret }}, restart the server:
  kubectl rollout restart statefulset/{{ include "submilli.fullname" . }} -n {{ .Release.Namespace }}
{{- end }}
