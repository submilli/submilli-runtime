The agent has written a useful program. To run it, the application selects a human-approved blueprint and binds the customer ID from trusted context. An agent can help draft the blueprint; a human owns its rules.

The application sends code to the authenticated server. It parses and type-checks supported TypeScript, then compiles it to WebAssembly. A type error stops the program before it runs.

Inside the server process, the runtime creates an execution instance and runs main. The program calls its billing package, which reads a local fixture standing in for a service.

Before returning charges, the package calls a permission check with the operation and customer ID. Its author placed this checkpoint; it is not inferred for every function.

The runtime compares the requested ID with the blueprint rule and the ID the application supplied. A match allows this lookup; another customer is denied.

The program totals permitted fixture records and returns its result: two charges, six thousand one hundred and fifty cents. Compilation checks the program. Runtime permission checks decide whether the requested operation and customer ID are allowed.
